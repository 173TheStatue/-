# 系统分析与设计 · Foxcore Retail 展会零售与销售追踪系统

## 案例与改进目标

17 名销售顾问、28 个 SKU、单周末最多并发展开 3 场跨区域展会。销售在纸质便签上记账，展后由合伙人深夜把数百张褶皱便签手工转录进多个离散 Excel，单场对账平均耗时 3.5 小时，佣金核算争议率约 12%，且一线可以在不被追踪的情况下击穿最低限价成交。

报告把这条业务链拆成可度量的指标，再倒推系统能力：

| 度量指标 | 手工基线 | 目标值 |
| :--- | :---: | :---: |
| 单场展会结业 → 佣金核算确认周期（首要指标） | 3.5 h | ≤ 0.25 h |
| 佣金核算争议率 | 12% | < 0.5% |
| 跨展会 / 跨品类经营分析报表编制周期 | ≈ 16 h（2 个工作日） | < 10 min |
| 低于最低限价的违规成交 | 时有发生 | 0（事前拦截） |

## 实现细节

**1. 中文长标识符断行**

`venue_id`、`NVARCHAR(MAX)`、`SalesConsultant` 这类在窄表格列里会溢出。`convert.py` 在 CamelCase 边界、下划线和左括号前插入断行点，26 张表因此没有出现 Overfull。

**2. SQL Server 而不是 MySQL**

全文按 T-SQL 书写：`IDENTITY(1,1)`、`NVARCHAR/NVARCHAR(MAX)`、`DATETIME2(0)`、`CHECK` 约束，排序规则 `Chinese_PRC_CI_AS`，驱动用 `pymssql`。
